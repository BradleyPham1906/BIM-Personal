# Parametric design: targeted application source audit

Research date: 2026-11-13. Audited source revision: `95b7aee4db8be1fc28c0fbe7befc7407fabd1dda`. This is a targeted single-reader source inspection, not a runtime test, full call-site audit, independent review, feature specification, or implementation approval. Behavior attributed to a function is conditional on reaching that function. P = direct source inspection; U = hypothesis or proposed test. Source files and further verification are listed below.

## Findings

| Area | Source evidence and qualification | Consequence / next test |
|---|---|---|
| Sketch constraints | P: `bimConResidual` includes coincidence, horizontal/vertical, distance, equal length, parallel, perpendicular, angle, point-on-line, midpoint and symmetry, operating on indices into sketch points. A fixed-point constraint is added transiently for a grip solve. `bimAddSketchConstraint` removes a newly added constraint if solving reports failure. This is not a complete feature or UI audit. | Test constraint reindexing, point deletion, dependent and duplicate equations, degeneracy, units and dimensions at small and large scales. |
| Solver and DOF | P: numerical central-difference Jacobian (`h=1e-6`) and damped iterations; the stopping condition compares squared norm to `tol=1e-9`, while `bimResolveSketch` rejects norm above `1e-3`. `bimEstimateSketchDOF` subtracts equation counts rather than computing Jacobian rank. Distance, angular and unnormalized cross/dot residuals are mixed; a single numeric norm is not directly a uniform physical-distance tolerance. | U: rank deficiency, scale and mixed residual magnitudes could give misleading DOF or acceptance. Test actual app with measured residuals; do not call it an observed failure. Choose and document scale-aware tolerances only after numerical experiments. |
| Pad | P: `doPad` flattens the sketch outline, creates a solid with a mesh and new ID, removes the input sketch from `A3D.objs`, then selects the result. `bimPushSketchTo` similarly replaces the sketch on a nonzero pull; returning to zero or cancelling restores a captured sketch snapshot. These paths do not attach an editable sketch/depth feature record to the created pad in the shown object constructor. | The existing operation is not evidence that the required editable sketch → pad history already exists. Test both UI paths, layers, undo, and whether other paths retain associations. |
| Pocket | P: `doPocket` picks its `s.on` target or searches candidate bounding boxes around the sketch center, builds a mesh tool and calls `csgSubtract`, rejecting an empty result. On success it removes both sketch and target and appends a new mesh solid and ID; the shown result constructor does not store a pocket feature/input relationship. It calls `pushUndo` before replacing the objects. | Test overlapping targets, concave/invalid outlines, no intersection, depth extremes, undo and save/reopen; validate intended target selection and no silent detachment. Do not infer kernel robustness from this source. |
| Dependencies | P: the existing graph rebuilds edges from recognized relationships and topologically orders dirty nodes. `bimGraphPropagate` warns on unresolved nodes and visits them once in model order, catches visitor exceptions and continues; result may contain `ok:true` together with nonempty `cycle` or `failed`. Kahn's unresolved nodes can include nodes downstream of a cycle, not just cycle members. Graph build failure returns `ok:false`. | A feature-history proposal cannot treat `ok` alone as proof of clean deterministic rebuild or claim cycles are blocked. Test cycle, downstream dependent, exception and graph-build failure; specify transaction/last-valid behavior without silently changing existing BIM propagation semantics. |
| Save and undo | P: `bimProjectRecord` includes `A3D.objs` and `history`; `save3d` serializes the record. `bimSnapshotState` JSON-serializes `objs` and an explicit set of other fields, and `bimRestoreState` restores `objs`; its listed fields are not identical to the project record. This does not establish persistence or undo of any proposed feature structure. | Test the actual chosen schema across disk export/import, browser storage, undo/redo, old projects, migration, IDs and broken references. A new top-level field must explicitly be audited against both save and snapshot/restore lists. |

## Acceptance experiment proposed — not run

1. Construct a 4 m × 3 m closed rectangle, pad 0.3 m, create a pocket; inspect the records after each operation. Change width to 5 m and pocket depth, check rebuild and intended target. Existing source indicates these direct commands consume inputs, so this should be treated as a gap to investigate, not promised current functionality.
2. Save/reopen and undo/redo exact sequence, including failed edits; assert feature inputs, object identity, last valid shape, selection and layer semantics. Compare persisted schema rather than screenshots alone.
3. Exercise redundant, inconsistent and nearly degenerate sketch constraints at multiple scales; measure each physical constraint independently, not just the aggregate residual. Check DOF against numerical Jacobian rank with a declared rank threshold.
4. Make a dependency cycle with an acyclic descendant and a throwing visitor; assert reported unresolved nodes, failures and which geometry changed. Establish the desired new failure semantics separately from the observed old ones.
5. Compare isolated JavaScript extension, a small WASM kernel candidate and hybrid representation against measured build/offline behavior, licensing and reproducible geometry results. No candidate is approved and no upstream code has been run in this audit.
